# WordRoom 통합 기획서

작성일: **2026-10-31 (한국 시간)**  
기준: 기능 커밋 **`bf9a164`**, 문서 정리 커밋 **`0f00671`**  
문서 성격: **현재 구현된 게임의 콘텐츠·규칙·플레이 흐름을 통합한 기획 기준**

이 문서는 기능 구현 순서와 개발 이력을 분리하고, 플레이어가 경험하는 현재 게임을 기준으로 정리한다. 본문에 정의한 기본 기능은 구현·자산 적용·커밋됐으며 사용자 검증 완료 통보가 있다. 품질 보완과 보류·제외 범위는 14절에 구분한다. 새로운 기능 추가나 정책 변경을 승인하는 문서는 아니다.

## 1. 게임 개요

WordRoom은 **단어 사이의 연관성을 따라 방을 선택하고 목표 단어를 찾아가는 1인칭 탐색 게임**이다. 혼자 플레이하거나 2~4명이 같은 지도를 공유하며 협동한다.

방 하나는 단어 하나를 나타낸다. 플레이어는 현재 단어와 상·하·좌·우에 연결된 단어를 보고 이동할 방향을 정한다. 방의 연결은 미리 고정된 미로 전체를 불러오는 방식이 아니라, 탐색 중 필요한 범위에 생성된다. 목표 단어는 고정된 목적이며 목표 방의 좌표는 게임 시작 때 플레이어에게 공개하지 않는다.

| 항목 | 기획 기준 |
|---|---|
| 장르 | 단어 연관성 기반 1인칭 탐색·협동 |
| 우선 플랫폼 | PC, 키보드·마우스 |
| 플레이 인원 | 단독 1명 / 협동 시작 인원 2~4명 |
| 핵심 목표 | 시작 단어의 방에서 목표 단어의 방까지 실제로 이동 |
| 협동 성공 | 참가자 중 한 명이 목표 방에 입장하면 팀 전체 성공 |
| 공간 | 같은 높이에서 네 방향으로 이어지는 정사각형 방 |
| 분위기 | 목재·황동·아이보리의 아카이브 공간과 부유형 관리 로봇 |
| 기록 수명 | 한 게임 동안 지도·방문·그림 유지, 새 게임에서 초기화 |
| 일반 플레이 제한 | 제한 시간·이동 횟수에 의한 종료를 적용하지 않음 |

기획의 중심은 단어를 보고 경로를 판단하는 선택, 지나온 길을 지도로 이해하는 탐색, 팀원이 나눠 찾은 정보와 메모를 합치는 협동이다. 별도 점수 경쟁·개인 순위는 제공하지 않는다.

## 2. 기본 플레이 구조

### 2.1 한 게임의 반복 흐름

1. 난이도를 선택하고 시작·목표 단어가 정해진 게임에 진입한다.
2. 현재 방과 네 방향 벽의 연결 단어를 확인한다.
3. 문을 바라보고 E로 연다. 이때 목적지 방 주변의 필요한 단어가 준비된다.
4. 열린 출입구를 직접 걸어 통과한다. 실제 입장으로 현재 위치·방문·목표 도달이 확정된다.
5. 필요하면 지도를 열어 경로와 팀원 위치를 보고 그림 메모를 남긴다.
6. 목표 방에 도달할 때까지 선택과 이동을 반복한다.
7. 결과 화면에서 시간·방문 기록을 확인하고 메인 메뉴로 돌아간다.

### 2.2 단독과 협동의 공통점·차이

| 항목 | 단독 | 협동 |
|---|---|---|
| 단어·공간·문 규칙 | 동일 | 동일 |
| 난이도 선택 | 본인 | 대기실 호스트 |
| 시작 | 데이터 준비·초기 배치 후 | 모든 참가자의 준비·데이터·초기 배치를 거친 공동 시작 |
| 탐색 위치 | 본인 | 참가자마다 독립 |
| 생성 지도·열린 문 | 본인 게임의 상태 | 팀 공유 상태 |
| 방문 정보 | 개인 고유 방문 | 팀 방문 합집합과 개인 방문을 구분 |
| 성공 | 본인 목표 입장 | 한 명의 목표 입장으로 팀 성공 |
| 지도 그림 | 본인 메모 | 작성자별 색으로 공유, 본인 것만 삭제 |
| 끼임방지 | 본인 게임당 1회 | 참가자마다 게임당 1회 |
| 결과 | 소요 시간·개인 방문 수 | 공동 시간·팀 방문 수·전원 개인 방문 수 |

## 3. 시작과 난이도

### 3.1 메인 메뉴

메인 메뉴는 **시작·협동·설정·종료**를 제공한다. 배경은 아카이브 공간의 분위기를 유지한다.

- **시작:** 단독 난이도 선택 → 게임 시작 → Gameplay 진입.
- **협동:** 협동 로비 → 방 생성 또는 입장 → 대기실 → 공동 시작.
- **설정:** 화면·조작·표시·음량 설정.
- **종료:** 애플리케이션 종료.

일반 플레이에서 시작·목표 단어를 직접 입력하지 않는다. 게임이 선택 범위 안에서 서로 다른 두 단어와 시드를 자동 선택한다. 개발용 Inspector 입력은 일반 플레이 UI와 구분한다.

### 3.2 난이도 기준

| 난이도 | 사용 어휘 범위 | 단어 길이 |
|---|---|---|
| 쉬움 | 빈도 상위 5,000개 단어 | 1~8글자 |
| 보통 | 빈도 상위 10,000개 단어 | 1~8글자 |
| 어려움 | 빈도 상위 15,000개 단어 | 1~8글자 |

기본 선택은 보통이다. 숫자는 **단어 수**이며 단어 쌍 수·글자 수·생성 방 개수가 아니다. 난이도는 게임이 사용할 어휘 범위를 정한다. 문 개수·이동 속도·일반 플레이 이동 제한을 바꾸는 설정이 아니다.

## 4. 단어와 방 생성 규칙

### 4.1 방의 단어

- 한 좌표에는 단어 하나를 확정한다. 생성된 좌표를 다시 방문해도 단어를 바꾸지 않는다.
- 같은 표기에 여러 뜻이 있어도 방을 특정 한 뜻에 고정하지 않는다. 여러 뜻이 연결의 근거가 될 수 있다.
- 목표 도달은 **목표와 같은 표기의 방에 실제 입장했는지**로 판정한다.
- 후보 좌표 기준 맨해튼 거리 3 이하에서는 같은 표기가 반복되지 않게 한다. 거리 4 이상에서는 다른 조건을 만족하면 반복될 수 있다.

### 4.2 생성 시점과 범위

시작 방은 논리 원점 `(0,0)`이며, 시작 시 주변 최대 네 방을 만든다. 이후 문을 열 때 목적지 방의 아직 비어 있는 이웃을 준비한다. 지나온 방이나 기존 생성 방이 있으므로 새로 생성할 방은 보통 최대 세 개이며 상황에 따라 더 적다.

미방문 방을 기준으로 주변을 재귀 생성하지 않는다. 지도를 열거나 방 표시 거리를 바꾸는 행위도 새 단어를 생성하지 않는다. **문 열기 때 준비하고, 실제 입장 때 이동·방문·성공을 확정**하는 두 단계를 유지한다.

### 4.3 연관성 판단과 목표 유도

후보 단어는 새 위치의 인접 방들과의 연관성을 기준으로 선택한다. 준비된 뜻 관계 DB를 우선 사용하고, 채우지 못한 위치는 fastText 유사도 기반으로 보충한다. 기준 완화와 배치 품질 비교를 거치므로 모든 연결이 같은 강도의 연관성을 보장하지는 않는다. 다른 방법이 없는 경우 약한 연결이 포함될 수 있다.

목표 단어와의 가까움을 후보 선택에 반영하는 목표 유도를 사용한다. 기존 배치 조건과 연결 품질의 우선순위를 유지하며, 협동에서는 **팀 전체 고유 방문 좌표 수**를 진행도로 사용한다. 시작 방을 포함하고 재방문·팀원 간 중복 방문·문 열기·방 생성만으로는 늘지 않는다.

현재 기본 유도는 **고유 방문 10개까지 강도 0, 이후 20개에 걸쳐 최대 0.09, 고유 방문 30개부터 최대 강도 유지**다. 단독은 본인 고유 방문 수, 협동은 팀 고유 방문 좌표 합집합을 사용한다. 강도는 목표 근접도를 후보 점수에 더하는 가중치이며 목표 출현 확률이나 도달 보장이 아니다. 2026-10-31 사용자 승인으로 이전 기본값(40개에 걸쳐 최대 0.03)에서 수치만 조정했으며, 실제 플레이 난이도와 목표 도달 변화는 아직 확인되지 않았다.

앞으로만 이동해도 목표가 나오는 현상은 KI-009로 기록·보류한다. 이번 수치 조정은 KI-009의 원인 해결이나 밸런스 확인 완료가 아니며, 원인 분석과 다른 생성 규칙 변경은 별도 결정 전까지 하지 않는다.

### 4.4 생성과 탐색의 한계

유한한 어휘·반복 제한·탐색 상한 때문에 주변 위치를 모두 채우지 못할 수 있다. 미생성 위치로 이동할 수 없으며, 한 방의 주변이 일부 비었다는 이유만으로 팀 전체 실패를 선언하지 않는다. 기존 방·연결을 통한 탐색을 유지한다.

확장형 탐색을 제공하지만 모든 데이터·시드에서 무한 생성이나 목표까지의 고정 길이를 보장하지 않는다. 같은 시드라도 문을 여는 순서와 생성 시점에 따라 지도 결과가 달라질 수 있다.

## 5. 공간·문·이동

### 5.1 공간 표현

정사각형 방이 상·하·좌·우로 연결되고 층 이동은 없다. 방향 벽에 연결된 방의 단어를 표시하며, 플레이어는 표시를 보고 이동할 문을 선택한다. 방 사이에는 연결당 하나의 공유 문을 사용하고 열린 상태를 유지한다.

| 항목 | 현재 기준값 |
|---|---|
| 방 중심 간격 | 6.2m |
| 출입구 폭·높이 | 1.3m·2.2m |
| 플레이어 높이·반지름 | 1.8m·0.3m |
| 시점 높이 | 1.6m |
| 기본 걷기 속도 | 3m/s |
| 문 상호작용 거리 | 화면 중앙에서 2m 이내 |
| 문 열림 | 0.5초 동안 본체가 2.2m 상승 |

### 5.2 문과 실제 입장

E로 문을 열면 목적지 방 주변 준비가 진행된다. 문이 열리는 연출과 실제 통과 허용을 구분하며, 준비와 바닥 표시가 끝나기 전에는 목적지로 통과하지 못하게 한다.

문을 여는 것만으로 목표에 도달하지 않는다. 플레이어가 출입구를 통과해 경계 바깥 0.15m 지점에 도달했을 때 입장을 판정한다. 정상 입장은 몸을 방 중앙으로 순간이동시키지 않는다.

단독은 생성 작업 중 기존 이동 잠금을 사용한다. 협동에서는 문 열기·입장 응답 대기마다 걷기 전체를 잠그지 않고 요청과 통로 상태로 제한한다. 입장 대기 중에는 출발 방과 진입 방을 잇는 통로를 유지하고 추가 입장을 제한한다. 미확정 위치를 호스트 승인 없이 확정 위치로 취급하지 않는다.

### 5.3 기본 조작

| 상황 | 입력 | 동작 |
|---|---|---|
| 일반 플레이 | W/A/S/D | 걷기 |
| 일반 플레이 | 마우스 이동 | 시점 회전 |
| 문 조준 | E | 문 열기·목적지 주변 준비 |
| 일반 플레이 | Tab | 지도 열기 |
| 지도 | Tab 또는 Esc | 지도 닫기 |
| 지도 | W/A/S/D·E | 걷기·문 상호작용 유지 |
| 지도 | 휠 | 확대·축소 |
| 지도 | 우클릭 드래그 | 지도 이동 |
| 지도 | 좌클릭·드래그 | 선택한 연필 또는 지우개 사용 |
| 일반 플레이 | Esc | 게임 메뉴 열기 |
| 게임 메뉴 | Esc | 설정에서 목록으로, 목록에서 게임으로 복귀 |

지도에서는 마우스를 UI에 사용하고 시점 회전·클릭에 의한 커서 잠금을 멈춘다. 지도에서 Esc를 누르면 지도만 닫으며 같은 입력으로 메뉴를 열지 않는다.

## 6. 협동 로비와 공동 시작

### 6.1 로비

협동 진입 후 연결 상태와 방 목록을 표시한다. 방 생성, 목록 입장, RoomCode 입장, 수동 새로고침, 다시 연결을 제공한다.

- 방 생성 시 최대 24자의 표시 이름과 최대 인원 2~4명을 정한다. 기본 최대 인원은 4명이다.
- 방 표시 이름과 8자리 RoomCode를 구분한다. 대기실에서 코드를 확인·복사할 수 있다.
- 목록 한 번 클릭은 즉시 선택만 한다. 같은 방을 0.3초 이내에 더블클릭하면 기존 입장 경로로 참가한다.
- 입장 버튼과 RoomCode 입장도 유지한다. 코드의 대소문자를 자동 변환하지 않으며 잘못된 코드로 새 방을 만들지 않는다.
- 입장 불가·정원 초과·목록에서 사라진 방과 작업 중 상태는 기존 검사로 차단한다.
- 새로고침은 로비를 나갔다 다시 참가해 전체 목록을 확인하는 작업이며 제한 시간은 15초다. 진행 중 방 생성·입장을 차단한다.
- 비밀번호·잠금방 기능은 제공하지 않는다.

### 6.2 대기실

방 이름·RoomCode·참가 인원·참가자 목록·호스트·준비 상태·난이도를 표시한다. 호스트만 난이도를 바꿀 수 있으며 변경하면 이전 준비를 무효화한다. 참가자는 현재 설정에 대해 다시 준비한다.

**시작 버튼은 호스트에게만 표시한다.** 게스트에게는 준비 버튼과 호스트가 시작한다는 안내를 제공한다. 일반 대기실에서 호스트가 바뀌면 표시 권한을 다시 계산한다.

시작 조건은 현재 설정이 확인된 상태에서 2명 이상 전원 준비이며 다른 시작 작업이 진행 중이지 않아야 한다. 버튼 표시 여부와 별개로 실제 시작 요청에서도 권한과 조건을 검사한다.

### 6.3 공동 시작

참가자의 데이터 패키지와 고정 생성 설정을 확인하고 같은 초기 월드를 공유한다. 전원의 초기 배치와 시작 준비를 거친 공통 시각에 탐색을 시작한다. 진행 중인 게임에는 새 참가자를 받지 않는다.

설정·데이터·초기 배치를 확인하지 못하면 성공한 시작으로 처리하지 않는다. 시작 전 호스트 변경이나 시작 중단은 대기실 복귀 규칙을 따른다.

## 7. 협동 탐색과 정보 공유

참가자는 서로 다른 방으로 자유롭게 이동할 수 있다. 방의 단어·공유 문·생성 이력·팀 방문·목표 결과는 팀이 공유하고 개인 위치·이동·방문 기록은 각각 유지한다. 한 사람의 이동 때문에 다른 사람의 몸이나 카메라가 이동하지 않는다.

호스트가 게임 상태를 확정한다. 참가자는 문 열기·입장·복귀를 요청하고 확정된 변경을 적용한다. 응답 대기·거절·미확정 상태를 성공으로 표시하지 않으며 상태 누락은 전체 사본으로 복구한다. 같은 요청을 중복 적용하지 않는다.

현재 요청 처리는 FIFO다. 근접 동시 요청에서 호스트를 우선하는 과거 합의의 시간 범위는 미정이므로, 현재 구현에 없는 우선 처리 정책을 적용됐다고 설명하지 않는다.

상대 플레이어는 부유형 관리 로봇으로 표시하고 서로 통과할 수 있다. 본인용 원격 로봇은 만들지 않는다. 참가자별 색상을 로봇·지도 마커·그림에 공통 사용한다. 상대 외형의 연속 위치·방향 표시는 논리 입장·방문·목표 확정과 구분한다.

## 8. 지도와 자유 그리기 메모

### 8.1 지도 정보

지도는 **현재 게임에서 생성된 방 전체**를 표시한다. 3D 방 표시 거리와 독립이며 아직 생성하지 않은 전체 공간을 미리 공개하지 않는다.

표시 항목은 방 단어, 방문·미방문 구분, 본인의 현재 방, 플레이어의 위치·방향, 생성된 목표 방, 방 연결, 참가자별 그림이다. 협동 방문 표시는 팀 공유 정보이며 개인 현재 위치와 구분한다. 단어는 각 방 아래 고정 위치에 표시한다.

본인 마커는 실제 몸의 위치·방향을 따르고 상대 마커는 수신한 최신 위치·방향을 사용한다. 지도의 상대 마커는 3D 로봇 표시 범위와 독립적으로 공개된 방에 표시한다. 첫 위치 수신 전·퇴장·3초 이상 수신 끊김에는 숨긴다.

휠 확대·축소, 우클릭 드래그 이동, 현재 위치로 중심 맞추기를 지원한다. 지도가 플레이어를 따라 매번 자동 이동하지는 않는다. 지도 개폐로 확대·이동과 게임 진행을 새 판으로 초기화하지 않는다.

### 8.2 그리기와 삭제

| 도구 | 동작 | 권한 |
|---|---|---|
| 연필 | 좌클릭은 점, 드래그는 연속 선 | 본인 작성 |
| 지우개 | 드래그 경로에 닿는 선의 일부를 잘라 삭제 | 본인 그림만 |
| 모두 지우기 | 본인이 남긴 그림 전체 삭제 | 본인 그림만 |

‘모두 지우기’는 추가 확인 창 없이 실행한다. 참가자별 색상으로 작성자를 구분한다. 그림은 화면 픽셀 대신 지도 좌표에 연결되어 확대·이동해도 같은 장소에 남고 크기도 함께 변한다.

기본 선 굵기는 0.04, 지우개 반경은 0.12 지도 단위다. 획당 최대 256점·작성자당 최대 128획·게임 전체 최대 16,384점으로 제한한다. 한도에 도달하면 안내하고, 지우개나 모두 지우기로 여유를 확보할 수 있다.

협동 그림은 호스트가 확정해 공유한다. 전송 대기 미리보기와 확정 상태를 구분하며 탐색 상태와 별도 그림 복구를 사용한다. 전체 그림의 확인·제한 재전송 후에도 일치를 확인하지 못하면 경고하고 완료로 처리하지 않는다.

### 8.3 커서와 입력 경계

연필·지우개·우클릭 이동 중 손 모양 커서를 사용하고 지우개에는 실제 범위를 나타내는 링을 표시한다. 도구 버튼 위와 일반 지도 밖에서는 기본 커서를 사용한다.

도구 버튼 위에서 시작한 클릭으로 지도에 그리지 않는다. 획 작성 중 지도 영역을 벗어나면 마지막 유효 지점에서 끝내고 누른 채 다시 들어와도 새 클릭 전까지 이어 그리지 않는다. 확대·이동·도구 변경·현재 위치 조작과 그리기가 섞이지 않게 한다.

지도 닫기·포커스 상실 때 진행 중 미리보기를 정리하고 커서 상태를 복원한다. 이미 확정된 그림은 지도 재개방 후에도 유지되며 새 게임·게임 종료 때 폐기한다. 별도의 텍스트 메모와 영구 저장은 제공하지 않는다.

## 9. 끼임방지

Esc 메뉴에서 **‘끼임방지 (1회)’**를 제공한다. 단독·협동 모두 **플레이어마다 한 게임에 한 번** 사용할 수 있다. 버튼 하단 설명 행은 없으며 사용 후에도 버튼은 표시한 채 비활성화한다.

| 구분 | 규칙 |
|---|---|
| 사용 가능 | 초기 배치가 끝난 진행 중 게임, 본인의 미확정 요청 없음, 사용 이력 없음 |
| 사용 불가 | 로딩·초기 배치 전·결과 확정 후·오류 정지·다른 로컬 요청 대기 중 |
| 목적지 | 시작 방 `(0,0)`의 안전한 바닥 중앙 |
| 적용 대상 | 버튼을 누른 플레이어만 |
| 사용 소비 | 논리 복귀가 확정될 때 |
| 미전송·거절 | 사용 횟수 유지 |
| 확정 후 실제 배치 실패 | 사용을 되돌리지 않고 기존 오류 안내·정지 처리 |
| 재사용 | 새 게임을 시작하면 다시 한 번 가능 |

기존 방·열린 문·생성 이력·이동 수·방문·탐색 경로·시간·그림을 보존한다. 복귀를 일반 이동·방문이나 목표 도달로 집계하지 않는다. 복귀 기록은 일반 경로와 별도로 유지한다.

협동에서는 호스트 확정 후 몸을 옮기고, 변경 누락 뒤 전체 사본으로 복구해도 같은 복귀를 다시 배치하지 않는다. 실제 바닥 배치에 성공한 뒤 메뉴를 닫고 조작을 재개한다. 재배치 시 방향은 정면으로 초기화되며, 지도가 열려 있으면 커서는 해제 상태를 유지한다.

## 10. 성공·시간·결과

### 10.1 성공 조건

목표 표기의 방에 실제 입장한 확정 상태가 성공 기준이다. 목표 방향의 문을 열거나 주변을 준비한 것만으로 성공하지 않는다. 협동은 한 명의 목표 입장으로 팀 전체 성공이며 결과는 한 번만 확정한다.

### 10.2 시간과 방문 집계

| 항목 | 기준 |
|---|---|
| 단독 시간 시작 | 로딩·초기 배치 뒤 실제 조작 가능한 최초 시점 |
| 단독 시간 종료 | 목표 방 경계 통과 시각 |
| 협동 시간 시작 | 전원 준비·초기 배치 뒤 공동 시작 시각 |
| 협동 시간 종료 | 호스트가 첫 목표 입장을 확정한 시각 |
| 시간에 포함 | 시작 후 메뉴·지도·포커스 상실·생성·통신·처리 대기 |
| 개인 방문 수 | 본인이 입장한 고유 좌표 수, 시작 방 포함 |
| 팀 방문 수 | 전원의 고유 방문 좌표 합집합, 팀원 간 중복 제외 |

재방문 횟수·방 생성 개수·일반 이동 수를 고유 방문 수와 혼동하지 않는다. 끼임방지는 고유 방문·일반 이동 집계를 늘리지 않는다. 시간을 표시할 수 없는 데이터에서는 임의로 만들어내지 않고 기존 안내를 유지한다.

### 10.3 결과 화면

단독은 목표 달성·소요 시간·개인 방문 방 수를 표시한다. 협동은 **팀 목표 달성·공동 소요 시간·팀 방문 방 수·참가자 전원의 개인 방문 방 수**를 표시한다. 협동 개인 행은 세션 참가자 순서대로 최대 4개이며 본인에게 ‘나’를 표시한다. 이름과 집계는 표시 시 고정하고, 현재 방 인원이나 로컬 타이머로 다시 계산하지 않는다.

결과 화면은 지도와 Esc 메뉴를 닫고 게임 입력을 차단한다. 마우스 커서를 해제하며 각 플레이어가 자기 메인 메뉴 버튼으로 게임을 종료한다. 협동은 방·연결의 소유 상태에 맞춰 정리한다. 결과 뒤 즉시 재시작·같은 대기실 복귀 기능은 제공하지 않는다.

이미 표시한 결과는 호스트 퇴장이나 연결 종료로 사라지지 않는다. 호스트 변경 전에 받은 최종 상태도 적용할 기회를 주되, 아직 받지 못한 결과나 추가 상태 복구가 필요한 누락까지 보장하는 기능은 아니다.

## 11. 게임 메뉴·설정·안내

### 11.1 Esc 메뉴

계속·설정·끼임방지 (1회)·메인 메뉴·종료를 제공한다. 메뉴를 열면 걷기·시점·E·클릭 잠금을 차단하고 커서를 해제한다. 메뉴를 닫는 입력이 곧바로 게임 조작으로 이어지지 않게 한다.

**메뉴와 지도는 게임 시간을 멈추지 않는다.** 협동에서 한 명이 메뉴를 열어도 다른 참가자의 탐색은 계속된다. 로딩·작업·결과의 입력 제한은 메뉴 입력 차단과 구분한다.

### 11.2 설정

| 설정 | 범위 | 기본값 |
|---|---|---|
| 방 표시 거리 | 맨해튼 반경 1·2·3칸 | 1칸 |
| 마우스 감도 | 0.2~3.0배 | 1배 |
| Y축 반전 | 켬·끔 | 끔 |
| 수직 시야각 | 60~90도 | 60도 |
| UI 크기 | 80~125% | 100% |
| 전체 음량 | 0~100% | 100% |
| 효과음 음량 | 0~100% | 100% |
| 화면 | 전체 화면·창 모드, 지원 해상도 목록 | 전체 화면·디스플레이 크기 |

방 표시 거리는 기존 생성 방 중 3D로 표시할 범위다. 각각 최대 5·13·25개이며 새 단어 생성 범위를 바꾸지 않는다. 지도 정보 범위도 줄이지 않는다.

UI 크기는 메뉴·HUD·안내·결과·지도에 공통 적용하고 3D 벽 단어는 변경하지 않는다. 개인 설정은 저장해 다음 실행에도 유지한다. 화면 변경은 15초 유지 확인을 거쳐 저장하며 취소·시간 초과 등에는 직전 상태로 복원한다. 첫 미확정 변경 뒤 종료·재실행의 복원 기준은 별도 보완 과제다.

### 11.3 HUD와 안내

현재 단어와 목표 단어를 좌상단 HUD에 표시한다. 현재 단어는 실제 입장 상태를 따르고, 목표는 게임 동안 고정한다. 방 벽의 연결 단어가 이동 선택을 돕는다.

작업·연결 대기와 거절·실패·종료 사유는 기존 안내 경로로 전달한다. 실제 완료되지 않은 작업을 성공으로 안내하지 않는다. 결과 UI를 사용할 수 없으면 목표 도달 안내와 Esc를 통한 메인 메뉴 복귀 경로를 유지한다.

## 12. 아트·사운드·표시 기준

목재 패널·황동 프레임·아이보리 글자를 중심으로 아카이브 분위기를 통일한다. 방과 문은 기존 아카이브 모델을 사용한다. 상대 플레이어는 동일한 부유형 관리 로봇 외형에 참가자별 강조색을 적용한다.

지도는 방문 방과 미방문 방을 명암으로 구분하고 현재 방과 생성된 목표를 테두리·기호로 구분한다. 단독 플레이어는 민트색을 사용하고 협동은 참가자별 색상을 사용한다. 겹친 마커를 피하려고 실제 위치를 옮기지 않는다.

메뉴 버튼은 짧은 클릭음을 사용한다. 전체 음량과 효과음 음량을 구분한다. 외부 배경 음악·문 효과음·발소리를 현재 구현된 사운드로 포함하지 않는다.

## 13. 데이터·운영·게임 종료

### 13.1 실행 데이터

게임은 미리 준비한 사전·관계·벡터 패키지를 읽는다. 현재 패키지는 15,000개 표기·48,317개 뜻·85,440개 관계 판정 레코드이며, 뜻 벡터 768차원과 표기 벡터 300차원을 사용한다. 관계 판정 수는 단어 수나 방 개수가 아니다.

Qwen 관계 판정과 벡터 생성은 사전 준비 작업이다. 플레이 중 Python·Qwen·외부 AI API를 호출해 단어를 생성하지 않는다. 협동 통신은 Photon PUN 2.56을 사용하며 현재 게임 메시지 형식은 v6다. 참가자 간 패키지와 게임 설정의 일치가 필요하다.

### 13.2 저장과 수명

개인 환경 설정은 저장한다. 게임의 방·문·방문·위치·그림·진행 시간은 세션 단위이며, 메인 메뉴 복귀나 새 게임에서 이전 탐색을 이어 불러오는 영구 저장은 제공하지 않는다.

### 13.3 이탈과 연결 종료

일반 참가자의 이탈은 상대 외형·표시 수명과 기존 세션 규칙으로 처리한다. 호스트 역할을 다른 참가자에게 넘겨 게임을 계속하는 기능은 제공하지 않는다.

결과 확정 전 호스트 변경은 기존 게임을 중단하고 대기실로 돌아가는 흐름을 사용한다. Playing 중에는 이미 수신된 최종 상태를 한 번 처리해 결과 확정 여부를 판단한다. 결과가 없으면 중단하고 게임 흐름이 응답하지 않으면 3초 후 중단한다. 결과가 이미 확정된 기기는 화면을 유지한다.

예상 밖 연결 종료를 자동 재접속이나 게임 상태 복원으로 처리하지 않는다. 기존 안내와 복귀·다시 연결 경로를 제공한다. 전체 사본으로 누락된 상태를 맞추는 기능은 이 재접속 기능과 구분한다.

## 14. 완료 범위와 남은 결정

### 14.1 현재 기능 범위

단독 시작·난이도·1인칭 이동·문·단어 생성·HUD·설정·결과, 협동 로비·준비·공동 시작·탐색/복구·원격 로봇·지도 참가자, 더블클릭 입장, 지도 자유 그리기/삭제/공유, 개인 게임당 1회 복귀, 협동 결과 UI, GUEST 시작 버튼 숨김은 현재 구현 범위에 포함한다.

이 기능들에 사용자 검증 완료 통보가 있다. 모든 데이터·시드·장시간 플레이·통신 실패·이탈 경계까지 일괄 확인됐다는 의미로 확대하지 않는다. 이번 기획서 작성에서는 코드·문서·자산을 읽었으며 Unity 실행·컴파일·테스트는 하지 않았다.

### 14.2 제외·보류·미정

| 구분 | 내용 | 현재 취급 |
|---|---|---|
| 현재 범위 제외 | 재접속·호스트 인계 | 사용자 결정에 따라 필수 구현 목록에서 제외 |
| 별도 요구 없음 | 텍스트 메모·영구 저장·결과 후 대기실 복귀/재시작 | 현재 제공하지 않음, 신규 요구로 별도 결정 |
| 후순위·보류 | Android·핑·별도 단어 능력 | 현재 PC 기본 기능 범위에 추가하지 않음 |
| 정책 미정 | 근접 동시 요청의 호스트 우선 시간 범위 | 구현은 FIFO 유지, 변경 전 결정 필요 |
| 밸런스 보류 | 목표 유도와 단순 전진 현상(KI-009) | 기록 유지, 원인 분석·생성 규칙 변경 보류. 유도 수치는 2026-10-31 사용자 승인으로 조정(효과 미확인) |
| 기존 수정 보류 | KI-001·011·013·014 | 기존 사용자 결정 유지 |

### 14.3 품질 보완 기록

KI-002(첫 미확정 화면 설정 복원), KI-003(표시 거리 갱신 중 입장 판정), KI-005(해상도 목록), KI-010(작은 지도 단어 풀), KI-015(부분 지도 마커 참조)는 조건부 보완 후보로 남긴다. Editor 도구의 부분 저장·사용자 설정 보존 문제 KI-006·007도 별도 기록을 유지한다. 기록 자체를 수정 승인으로 해석하지 않는다.

로비 목록 누락 KI-012는 **Photon region 문제라는 사용자 추정과 서버 설정 변경 후 현재 재발 없음 보고**를 반영한다. 원인이 확정됐다고 기록하지 않고 재발 시 점검한다. 현재 정상 동작하는 목록·새로고침을 다시 미구현으로 되돌리지 않는다.

상세 조건·근거·우선순위는 [Known Issues](02_Known_Issues.md)를 따른다.
