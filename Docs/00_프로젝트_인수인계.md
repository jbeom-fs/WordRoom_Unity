**협동 상태·탐색:** 공유 월드·개인·세션 분리(`48e25a0`)를 바탕으로 호스트 `SessionCoordinator`가 Prepare·Enter를 확정한다(`b209aef`). 게스트는 요청·확정 변경분·전체 사본을 사용하고 독자적으로 생성하지 않는다. 중복 요청 결과 기록·조회, 적용 Ack, 전체 상태 복구, 팀/참가자별 Stop·StopAck가 있다. 협동 목표 유도는 팀 고유 방문 좌표 수, 최근 생성 이력은 월드 공용 하나이며 기존 보정 수치는 유지한다.

**협동 로비·목록:** 로비·대기실 `b604d0d`, 수동 새로고침 `8928210`, 더블클릭 입장 `1968b2f`가 구현됐다. 더블클릭은 같은 행·방·Binding·포인터의 0.3초 이내 입력으로 판정하고 기존 입장 검사를 공유한다. 단일 클릭 선택은 즉시 처리하며 입장 버튼·RoomCode 시도 전에도 클릭 기록을 지운다. 대기실 시작 버튼은 호스트에게만 보이고 게스트는 준비 버튼과 안내를 사용한다. 새로고침은 전체 목록 확인·15초 제한·중복 작업 차단·늦은 응답 정리를 유지한다. **KI-012는 사용자 보고상 Photon region 문제로 추정되며 서버 설정 변경 후 현재 재발하지 않는다.** 변경한 설정 값·원인 분리 결과는 제시되지 않았으므로 원인 확정이나 코드의 근본 해결로 기록하지 않는다. 진단·새로고침은 유지하고 재발 시 점검한다.

**공동 시작·이동의 현재 범위:** 공동 시작·초기 월드 동기화는 `7a5e5a5`로 커밋됐다. 사용자는 시작 가능을 확인했고 이후 협동 탐색과 이동 개선에도 확인 완료를 통보했다. 게스트의 문 열기·입장 요청마다 걸던 걷기 잠금은 `c168a11`에서 제거했다. Prepare/Enter 대기는 분리하고 입장 대기 중 두 방을 잇는 통로만 허용한다. 실제 몸과 호스트 확정 위치를 분리하며 정상 수락 때 재배치하지 않는다. 진행 중 이탈·호스트 변경·전송 실패 주입 등 개별 경계 사례가 모두 통과한 것으로 확대하지 않는다.

**원격 로봇·지도:** 부유형 관리 로봇 ArchiveRobot_v1을 제작·FBX로 내보내고 URP 재질·ArchiveRobotRemote 프리팹·Gameplay 참조까지 커밋했다(`964effb`). 자기 로봇은 만들지 않고 상대만 표시한다. 실제 몸의 위치·yaw를 별도 Unreliable Pose(116)로 보내며 로봇은 0.2초 지연 보간·3초 수신 끊김 숨김을 쓴다. 지도는 최신 포즈를 그대로 표시하고 로봇의 3D 표시 범위와 독립이다. 참가자 색은 양쪽에서 동일하다. 사용자는 로봇 검증 완료와 지도 씬 적용을 통보했다. 지도 전체 항목의 실행 검증 완료 통보는 별도 없으며 보간 시각·보정 직후 전송 문제는 사용자 결정으로 보류했다.

**지도 메모·협동 공유 (`170a7e2`):** 우클릭 드래그 이동·휠 확대, 좌클릭 연필/부분 지우개, 본인 그림 모두 지우기와 도구 커서·지우개 범위 링을 제공한다. 지도 좌표에 저장하며 참가자 색상으로 공유한다. 획당 256점·작성자당 128획·전체 16,384점이며 지도 재개방 시 유지하고 새 게임에서 지운다. 호스트 확정 그림은 탐색과 별도 순번·수신함을 사용하고 사본 복구 token·SketchAck·제한 재전송을 제공한다.

**정책·결과·끼임방지 (`bf9a164`):** 요청 처리는 시간 범위 미정으로 임시 FIFO다. 협동 결과는 한 번 확정한 공동 시간·팀 고유 방문 수·참가자 전원 최대 4명의 개인 방문 수를 표시하고 본인 행에 ‘나’를 붙인다. 각자 메인 메뉴로 복귀하며 대기실 복귀·재시작은 추가하지 않았다. Playing 중 호스트 변경은 이미 수신한 상태를 처리한 뒤 결과 확정 여부로 중단을 결정한다(게임 흐름 미응답 시 3초 후 중단). 누락으로 추가 복구가 필요한 결과나 미수신 결과를 보장하는 인계 기능은 아니다. 끼임방지는 **플레이어당 게임 1회**, 요청자만 시작 방에 복귀하며 이동·방문·시간·그림을 유지한다. 버튼은 **‘끼임방지 (1회)’**, 하단 설명 없음, 사용 후 표시한 채 비활성이다. 횟수는 코디네이터와 로컬 확정 상태에서 검사하며, 확정 후 배치 실패도 사용을 되돌리지 않는다. 재배치 중 지도 커서 해제 상태를 유지한다.

## 1. 작업 종료 상태

**단독 기본 흐름과 협동 로비·공동 시작·탐색·원격 로봇·지도·자유 그리기 메모·끼임방지·협동 결과 UI는 구현·자산 적용·커밋됐다.** 최신 세 기능 커밋에 사용자 검증 완료 통보가 있다. 개별 실패 주입·장시간·모든 이탈 조건의 통과를 추정하지 않는다. 재접속·호스트 인계는 현재 범위 제외다.

- 메인: 시작·설정·종료 → 난이도(쉬움·보통·어려움) → 게임 시작.
- 실제 게임: `MainMenu` → `Gameplay`. `RoomGenerationDebug` 씬은 개발용으로 보존.
- 난이도별 빈도 상위 **5,000 / 10,000 / 15,000개 단어**, 길이 1~8글자. 시작·목표는 범위 안에서 서로 다르게 자동 선택한다. 일반 사용자에게 단어 입력을 받지 않는다.
- E로 문을 여는 시점에 목적지 방의 주변 단어를 생성한다(`Prepare`). 실제 입장에서는 이동·방문·목표 판정만 한다(`Enter`). 입장 시 다시 생성하지 않는다.
- 방 표시 거리는 맨해튼 반경 1·2·3칸, 최대 5·13·25개. **이미 생성된 방의 표시 범위이며 생성 범위가 아니다.** 설정 변경만으로 단어를 생성하지 않는다.
- 현재·목표 HUD는 좌상단. 문 열기·생성 대기 진행 자막은 표시하지 않는다.
- Esc 게임 메뉴: 계속·설정·끼임방지 (1회)·메인 메뉴·종료. 메뉴 입력 차단과 생성 중 이동 잠금은 별도다. Time.timeScale을 멈추지 않는다.
- 고정 UI는 `Assets/Prefabs/UI` 프리팹과 씬 참조를 사용한다. 런타임 조립·삭제 경로를 제거했고, 프레임 두께는 4로 통일했다.
- 결과 화면: 처음 실제 조작 가능한 시점부터 목표 방 경계 통과 감지까지의 실시간과 고유 방문 방 수(시작·목표 포함)를 고정 표시한다. 측정 시작 후 메뉴·지도·생성 대기도 시간에 포함하며 메인 메뉴 버튼으로 복귀한다.
- 단독 지도: 생성된 전체 방·단어, 방문·미방문, 현재 방, 밝은 민트 플레이어 위치·방향, 생성된 목표와 연결선을 표시한다. 3D 표시 거리와 독립이며 미생성 영역은 공개하지 않는다.
- 지도는 **Tab**으로 열고 닫으며 Esc는 지도만 닫는다. 지도 중 **WASD·E 문 열기 허용**, 마우스는 지도 확대·이동에 사용해 시점 회전·클릭 커서 잠금은 멈춘다. 단어는 방 아래 고정 위치이며 플레이어에 따라 옮기지 않는다.
- 사용자 설정은 유지하지만 세션 지도·단어·문 상태를 영구 저장하지 않는다.

문서 갱신 직전 HEAD는 `bf9a164`이고 작업 트리는 깨끗했다. 이번 요청은 프로젝트 문서만 갱신하며 개발일지·코드·씬·프리팹·설정은 보존한다. 스테이징·커밋하지 않는다.

## 4. 현재 규칙과 주의점

- 방 간격 **6.2m**, 실내 6×6m, 벽 두께 0.1m, 출입구 폭 **1.3m**·높이 **2.2m**. 벽 경계는 중심에서 3.1m, 입장 기준은 경계 밖 0.15m다.

- 플레이어 높이 1.8m, 반지름 0.3m, 시점 1.6m, WASD 3m/s. 감도는 기본 0.1에 설정 배율을 한 번 곱한다.
- HUD는 아카이브 분위기의 짙은 목재·황동·아이보리. 현재·목표 두 줄만 표시한다. 안내용 PlayHint와 별도다.
- 플레이어 활성 판정·연결 해제·교체·시점 기준 보존은 후속 문 구현에서 보완됐다. 10월 21일 문서의 전환 문제 2건을 현재 미수정으로 되살리지 않는다.
- 표시 반경 1·2·3, 감도 0.2~3배, Y축 반전, 시야각 60~90도, UI 크기 80~125%, 전체·효과음 음량, 화면 모드·해상도를 제공한다. 화면 변경은 15초 확인 후 저장한다. 예외는 아래 미해결 사항 참조.

- 중복 금지는 후보 좌표 기준 맨해튼 거리 3 이하. 표시 반경이나 한 번에 추가하는 방 수와 별개다.
- 목표 판정은 표기 일치. 준비만으로 성공하지 않고 실제 입장해야 성공한다.
- 표시 방을 풀에 반환해도 지도·단어·문 상태는 남는다. 새 판·메인 복귀와 표시 거리 이탈을 구분한다.
- 같은 시드라도 문을 여는 순서·생성 시점에 따라 이전 버전과 지도 결과가 달라질 수 있다. Python과 수치상 완전 일치도 보장하지 않는다.

## 6. 미해결 사항과 다음 작업

[Known Issues](02_Known_Issues.md)에 상태·조건·근거를 기록했다.

- **KI-001**: Prepare·Enter 일부 경로의 취소 확인 누락. 낮은 우선순위, 사용자 결정으로 수정 보류. Esc·Alt+Tab만으로 발생하는 일반 탐색 오류로 설명하지 않는다.
- **KI-002 / P2**: 첫 화면 설정 미확정 상태로 앱 종료 후 재실행하면 복원 기준이 없을 수 있음.
- **KI-003 / P3**: 표시 반경 재캡처 중 busy로 입장 판정은 멈추지만 걷기를 잠그지 않음. 작업 지연과 이동 경로 변경이 겹칠 때 판정 누락 가능성.
- **KI-004 / P3**: UI 크기 트랙 최초 누름 순서 문제. `0c5d217`에서 LateUpdate 판정으로 수정·커밋. 개별 재현 조건의 사용자 확인 기록은 별도 없음.
- **KI-005 / P3**: 창 모드 해상도 목록에 현재 크기를 다시 넣어 디스플레이 크기 제한 우회 가능.
- **KI-006 / P2**: 이전 모델 도구 검토 사항. 문 프리팹 저장 후 방 저장이 실패하면 부분 변경이 남지만 공통 로그는 저장하지 않았다고 안내함.
- **KI-007 / P3**: 모델 교체 도구 재실행이 기존 재질·조명 값을 다시 설정함. 중복 방지와 사용자 속성 보존은 별개.
- **KI-008 / P3**: HUD 비활성화 뒤 재생성 문제. `0c5d217`에서 화면·제어 분리와 활성 검사로 수정·커밋. 개별 비활성화 조건의 사용자 확인 기록은 별도 없음.
- **KI-009 / 게임 밸런스**: 목표 보정 때문에 앞으로만 이동해도 목표 단어가 나오는 현상을 사용자가 보고했다. 정확한 영향·재현 조건은 미분석이며, 사용자 결정으로 기록만 유지하고 수정은 보류한다. 생성 코드·보정 설정을 임의로 바꾸지 않는다.
- **KI-010 / P2**: 지도 단어 풀을 1~8개로 줄이면 용량 계산의 종료 조건을 만족할 수 없어 메인 스레드가 무한 반복할 수 있다. 기본 364개와 별개인 코드 검토 위험, 미수정·수정 범위 미합의.
- **KI-011 / P2**: 협동 중단 후 준비 초기화용 설정 순번의 서버 확인 전에 이전 준비로 재시작 가능. 코드 검토 위험, 사용자 결정으로 후속 수정 보류.
- **KI-012 / 현재 재발 없음(사용자 보고)**: Photon region 문제로 추정, 서버 설정 변경 후 현재 발생하지 않음. 원인 확정·비교 재현은 미확인이다. 진단·수동 새로고침은 유지하며 당장 원인 분석을 다음 필수 작업으로 잡지 않고 재발 시 점검한다.
- **KI-013 / P2**: 한 프레임에 꺼낸 포즈에 같은 시각을 기록해 원격 로봇 보간이 끊길 수 있다. 사용자 검증 완료 뒤 수정 보류 결정.
- **KI-014 / P3**: 위치 보정 횟수가 바뀌어도 최대 0.1초 전송 간격을 기다린다. 즉시 전송 설명과의 차이이며 사용자 결정으로 수정 보류.
- **KI-015 / P3**: 원격 지도 마커 배열 길이만 세어 부분 null 참조를 표시 가능 슬롯으로 간주한다. 구성 도구도 하나만 연결되면 건너뛴다. 기본 3개 연결은 정상, 미수정·수정 범위 미합의.

1. **기존 문제의 수정 범위 결정:** KI-010(작은 지도 단어 풀), KI-002(첫 미확정 화면 설정) 및 KI-003·005·006·007·015 보완 후보. 기록은 수정 승인이 아니며 사용자 요청 시 구현 프롬프트를 작성한다.
2. **요청 순서 정책 결정:** 현재 FIFO 유지 여부와 근접 동시 호스트 우선의 시간 범위를 구체화한다. 임의로 정책을 바꾸지 않는다.
