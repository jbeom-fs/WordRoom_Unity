**2026-10-27 진행 중 추가:** [협동 상태 분리 설계안](WordRoom_협동상태분리_설계.md)을 작성했다. 사용자 합의로 **협동 목표 유도 진행도는 팀 전체의 고유 방문 좌표 수**를 사용한다. 시작 좌표를 포함하고 재방문·팀원 간 중복 방문은 추가로 세지 않으며, 기존 보정 수치는 유지한다. 다른 협동 정책은 별도 결정하고 코드는 아직 구현하지 않았다. 사용자 결정으로 플레이어의 최종 외형은 애니메이션 필요성을 최소화한 간단한 로봇을 추후 추가하고, 그전에는 적당한 크기의 박스로 임시 표시한다. 박스·로봇 모델은 아직 구현하지 않았다.

**같은 날 정책 추가 합의:** 입력은 호스트 도착 시각 기준 선착순이며 게스트가 먼저면 게스트 우선, 근접 동시에는 호스트 우선이다(근접 동시 시간 범위 미정). 협동 결과는 팀·개인 고유 방문 수를 모두 표시한다. 협동 시간은 전원 데이터 준비·초기 배치 후 공동 시작부터 첫 목표 입장 호스트 확정까지이며, 시작 이후 메뉴·지도·생성·통신 대기를 포함한다. 최근 생성 단어 이력은 월드 전체에서 하나로 공유·관리한다. Esc 게임 메뉴에는 끼임방지 버튼을 추가해 누른 플레이어를 맨 처음 방으로 복귀시킨다. 복귀 중 상태·표시·시간·방문 기록 처리의 세부 제안은 설계 문서 4절 참고. 설계 결정만 반영했고 코드 미구현이다.

## 1. 작업 종료 상태

**단독 플레이의 고정 UI 사전 배치, 목표 도달 결과·시간·방문 집계, 탐색 지도까지 구현·씬 적용·커밋됐다.** 사용자는 UI 구성 완료, 결과 화면 완료, 최종 지도 기능 확인 완료를 통보했다. 에이전트의 실행 확인이나 모든 경계 사례·성능 항목의 통과를 뜻하지 않는다. Photon 협동, 재접속·호스트 인계, 팀 공유 지도·그림은 아직 없다.

- 메인: 시작·설정·종료 → 난이도(쉬움·보통·어려움) → 게임 시작.
- 실제 게임: `MainMenu` → `Gameplay`. `RoomGenerationDebug` 씬은 개발용으로 보존.
- 난이도별 빈도 상위 **5,000 / 10,000 / 15,000개 단어**, 길이 1~8글자. 시작·목표는 범위 안에서 서로 다르게 자동 선택한다. 일반 사용자에게 단어 입력을 받지 않는다.
- E로 문을 여는 시점에 목적지 방의 주변 단어를 생성한다(`Prepare`). 실제 입장에서는 이동·방문·목표 판정만 한다(`Enter`). 입장 시 다시 생성하지 않는다.
- 방 표시 거리는 맨해튼 반경 1·2·3칸, 최대 5·13·25개. **이미 생성된 방의 표시 범위이며 생성 범위가 아니다.** 설정 변경만으로 단어를 생성하지 않는다.
- 현재·목표 HUD는 좌상단. 문 열기·생성 대기 진행 자막은 표시하지 않는다.
- Esc 게임 메뉴: 계속·설정·메인 메뉴·종료. 메뉴 입력 차단과 생성 중 이동 잠금은 별도다. Time.timeScale을 멈추지 않는다.
- 고정 UI는 `Assets/Prefabs/UI` 프리팹과 씬 참조를 사용한다. 런타임 조립·삭제 경로를 제거했고, 프레임 두께는 4로 통일했다.
- 결과 화면: 처음 실제 조작 가능한 시점부터 목표 방 경계 통과 감지까지의 실시간과 고유 방문 방 수(시작·목표 포함)를 고정 표시한다. 측정 시작 후 메뉴·지도·생성 대기도 시간에 포함하며 메인 메뉴 버튼으로 복귀한다.
- 단독 지도: 생성된 전체 방·단어, 방문·미방문, 현재 방, 밝은 민트 플레이어 위치·방향, 생성된 목표와 연결선을 표시한다. 3D 표시 거리와 독립이며 미생성 영역은 공개하지 않는다.
- 지도는 **Tab**으로 열고 닫으며 Esc는 지도만 닫는다. 지도 중 **WASD·E 문 열기 허용**, 마우스는 지도 확대·이동에 사용해 시점 회전·클릭 커서 잠금은 멈춘다. 단어는 방 아래 고정 위치이며 플레이어에 따라 옮기지 않는다.
- 사용자 설정은 유지하지만 세션 지도·단어·문 상태를 영구 저장하지 않는다.

문서 갱신 직전 HEAD는 `430dfbb`, 작업 트리는 깨끗했다. 이번 요청은 프로젝트 문서와 오늘자 개발일지만 작성·갱신하며 스테이징·커밋하지 않는다.

## 2. 반드시 유지할 사용자 규칙

1. 구현 요청에는 **구현 프롬프트를 작성**한다. 직접 코드 수정 요청으로 해석하지 않는다. 문서 작성 요청은 문서만 수정할 권한이다.
2. Unity 실행·컴파일·빌드·테스트·자동 탐색·재현·자동 검증은 사용자가 직접 한다. 에이전트는 실행하거나 구현 프롬프트에서 실행을 지시하지 않는다.
3. 별도 명시적 요청 없이 Python, 모델, 데이터 export·verify·fixture를 실행하지 않는다. 파일을 읽는 검사라도 Python 금지에 예외를 만들지 않는다.
4. 코드·문서·Git 읽기는 가능하다. 코드 검토와 실제 동작 확인을 구분한다.
5. 사용자가 요청하기 전에 구현 프롬프트를 먼저 작성하지 않는다. 기존 사용자 코드·씬·모델·재질·설정을 보존한다.
6. 스테이징·커밋·푸시는 명시적 요청 없이 하지 않는다. 커밋 메시지 추천은 실행 권한이 아니다.
7. 커밋 메시지는 한국어 제목과 본문을 제공하고, **검증 관련 문구를 붙이지 않는다.** 검증은 사용자가 관리한다.
8. 프롬프트는 가능한 한국어·영어로 작성하되, **프롬프트 안에 사용 언어를 지시하지 않는다.** 완료 보고는 한국어로 한다.
9. 설명은 간결하게 하되 조건·원인·확인 범위는 생략하지 않는다. 방향은 상·하·좌·우로 표기한다.
10. 구현 전 가정·불확실성·대안을 밝히고, 가장 단순한 해결에 필요한 부분만 기존 스타일대로 바꾼다. 성공 기준·확인 방법은 제시하되 실행 검증은 하지 않는다.
11. 개발일지는 **그날의 전체 작업을 마칠 때만** `D:\Pro_KW\DebLogs\YYYY-MM-DD_WordRoom_개발일지.md`에 작성·갱신한다. 개별 요청 완료나 작업 진행 중에는 개발일지를 갱신하지 않는다. 일지는 사용자 관점에서 작업·문제·원인·해결·확인 범위·다음 과제를 기록한다. 관련 프로젝트 문서는 필요할 때 갱신하며 자동 스케줄은 없다.
12. KI-001은 사용자가 **기록만 유지**하기로 결정했다. 다른 작업에 섞어 고치지 않는다.
13. KI-009 목표 보정·단순 전진 현상도 기록만 유지하고 수정은 보류한다. 생성 규칙·보정값을 임의로 바꾸지 않는다.

## 4. 현재 규칙과 주의점

- 방 간격 **6.2m**, 실내 6×6m, 벽 두께 0.1m, 출입구 폭 **1.3m**·높이 **2.2m**. 벽 경계는 중심에서 3.1m, 입장 기준은 경계 밖 0.15m다.
- 문은 공유 연결당 하나, 본체만 **0.5초 동안 2.2m 상승**한다. 열린 연결 상태는 인스턴스와 분리해 세션 동안 유지한다.
- 문 본체가 완전히 열리고, 현재 방과 표시된 이웃 방을 연결하며, 목적지 주변 준비가 처리돼야 PassageBlock을 해제한다. 일부 미생성은 준비 실패와 다르다.
- E는 화면 중앙 2m Ray. 생성 요청 중 이동·E는 잠그고 시점·중력·Esc는 유지한다. 표시 실패는 Halt로 정지하며 Move/Enter를 되돌리거나 자동 재시도하지 않는다.
- 입장 후 방·문·표지판 표시와 도착 바닥을 확인한 뒤 이동을 재개한다. 기존 위치·시점을 유지하며 매번 PlaceAt하지 않는다.
- 플레이어 높이 1.8m, 반지름 0.3m, 시점 1.6m, WASD 3m/s. 감도는 기본 0.1에 설정 배율을 한 번 곱한다.
- HUD는 아카이브 분위기의 짙은 목재·황동·아이보리. 현재·목표 두 줄만 표시한다. 안내용 PlayHint와 별도다.
- 플레이어 활성 판정·연결 해제·교체·시점 기준 보존은 후속 문 구현에서 보완됐다. 10월 21일 문서의 전환 문제 2건을 현재 미수정으로 되살리지 않는다.
- 표시 반경 1·2·3, 감도 0.2~3배, Y축 반전, 시야각 60~90도, UI 크기 80~125%, 전체·효과음 음량, 화면 모드·해상도를 제공한다. 화면 변경은 15초 확인 후 저장한다. 예외는 아래 미해결 사항 참조.
- 논리 지도는 단일 플레이어 Position·Moves·Path 구조다. 네트워크만 붙여 자유 분산 탐색이 완성되지 않는다. 공유 월드와 플레이어별 상태를 먼저 분리한다.
- 일반 플레이 이동 제한은 꺼짐. `MaxMoves=300`만으로 활성화되지 않는다.
- 중복 금지는 후보 좌표 기준 맨해튼 거리 3 이하. 표시 반경이나 한 번에 추가하는 방 수와 별개다.
- 목표 판정은 표기 일치. 준비만으로 성공하지 않고 실제 입장해야 성공한다.
- 표시 방을 풀에 반환해도 지도·단어·문 상태는 남는다. 새 판·메인 복귀와 표시 거리 이탈을 구분한다.
- 같은 시드라도 문을 여는 순서·생성 시점에 따라 이전 버전과 지도 결과가 달라질 수 있다. Python과 수치상 완전 일치도 보장하지 않는다.

## 6. 미해결 사항과 다음 작업

[Known Issues](02_Known_Issues.md)에 상태·조건·근거를 기록했다.

- **KI-001**: Prepare·Enter 일부 경로의 취소 확인 누락. 낮은 우선순위, 사용자 결정으로 수정 보류. Esc·Alt+Tab만으로 발생하는 일반 탐색 오류로 설명하지 않는다.
- **KI-002 / P2**: 첫 화면 설정 미확정 상태로 앱 종료 후 재실행하면 복원 기준이 없을 수 있음.
- **KI-003 / P3**: 표시 반경 재캡처 중 busy로 입장 판정은 멈추지만 걷기를 잠그지 않음. 작업 지연과 이동 경로 변경이 겹칠 때 판정 누락 가능성.
- **KI-004 / P3**: UI 크기 트랙 최초 누름 순서 문제. `0c5d217`에서 LateUpdate 판정으로 수정·커밋. 개별 재현 조건의 사용자 확인 기록은 별도 없음.
- **KI-005 / P3**: 창 모드 해상도 목록에 현재 크기를 다시 넣어 디스플레이 크기 제한 우회 가능.
- **KI-006 / P2**: 이전 모델 도구 검토 사항. 문 프리팹 저장 후 방 저장이 실패하면 부분 변경이 남지만 공통 로그는 저장하지 않았다고 안내함.
- **KI-007 / P3**: 모델 교체 도구 재실행이 기존 재질·조명 값을 다시 설정함. 중복 방지와 사용자 속성 보존은 별개.
- **KI-008 / P3**: HUD 비활성화 뒤 재생성 문제. `0c5d217`에서 화면·제어 분리와 활성 검사로 수정·커밋. 개별 비활성화 조건의 사용자 확인 기록은 별도 없음.
- **KI-009 / 게임 밸런스**: 목표 보정 때문에 앞으로만 이동해도 목표 단어가 나오는 현상을 사용자가 보고했다. 정확한 영향·재현 조건은 미분석이며, 사용자 결정으로 기록만 유지하고 수정은 보류한다. 생성 코드·보정 설정을 임의로 바꾸지 않는다.
- **KI-010 / P2**: 지도 단어 풀을 1~8개로 줄이면 용량 계산의 종료 조건을 만족할 수 없어 메인 스레드가 무한 반복할 수 있다. 기본 364개와 별개인 코드 검토 위험, 미수정·수정 범위 미합의.

KI-002·003·005·006·007·010은 미수정이며 수정 범위를 합의하지 않았다. KI-004·008은 수정 커밋과 개별 확인 기록을 구분한다. KI-001·009의 사용자 보류 결정과 혼동하지 않는다.

결과 화면과 단독 지도는 완료되어 다음 구현 대상으로 되돌리지 않는다. 후속 후보는 남은 이슈 처리 범위 결정, 장시간 탐색 성능·시야 검토, 공유 월드와 플레이어별 상태 분리·Photon, 재접속·인계, 팀 공유 지도·그림이다. 다음 착수 작업은 아직 새로 지정되지 않았다. 사용자 요청에 맞춰 기준을 정리하고 구현 프롬프트를 작성한다.
