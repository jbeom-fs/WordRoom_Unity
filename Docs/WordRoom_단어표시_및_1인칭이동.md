# WordRoom — 벽별 단어 표시와 방 안 1인칭 이동

갱신일: **2026-10-21 (한국 시간)**  
기준 커밋: **`cf1dd59`**

벽별 단어·한글 출력은 `5c6bef4`, 방 안 이동은 `cf1dd59`에서 구현·사용자 확인·커밋 완료했다. 사용자 확인은 통보된 범위이며 개별 경계 시험 전체의 통과를 뜻하지 않는다. 이 문서 갱신에서는 코드·프리팹·씬을 읽기만 했고 Unity 실행·컴파일·빌드·테스트·자동 검증을 하지 않았다.

## 1. 현재 가능한 플레이와 다음 경계

시작 방이 생성되면 플레이어가 바닥 위에 배치되고 WASD·마우스로 방 안을 걷고 둘러본다. 벽 표지판에는 그 방향의 이웃 방 단어가 보인다. **문은 모두 닫혀 있으며 여는 입력이 없다.** 실제 경계 통과에 따른 논리 좌표·방문·주변 생성 연동도 아직 없다. 방 안을 걷는 것만으로 엔진 이동 수나 방문 방 수가 늘지는 않는다.

다음 기능은 문 열기 상호작용·상승 애니메이션과 열린 상태 유지, 문 통과 시 정확히 한 번 방 진입 처리, 이후 주변 생성·표시 갱신이다. E키는 제안 상태이며 열기 거리·시간과 생성 중 출입 정책은 후속 결정 대상이다. 현재 방 단어·항상 보이는 목표 HUD도 남아 있다.

## 2. 벽별 단어 표시 (`5c6bef4`)

### 프리팹과 폰트

| 방향 | 방 기준 위치 | 텍스트 경로 |
|---|---|---|
| 상 | +Z | `Wall_Up/WordTag/Word/WordText` |
| 하 | -Z | `Wall_Down/WordTag/Word/WordText` |
| 좌 | -X | `Wall_Left/WordTag/Word/WordText` |
| 우 | +X | `Wall_Right/WordTag/Word/WordText` |

네 벽 전체를 묶는 부모 이름을 영어로 바꿨다. `WordTag` 끝 공백은 제거했다. 기존 `Word` 메시 표시 면을 유지하고 `WordText` TMP 3D 자식을 추가했다. 표시 면은 약 0.45×0.27m, 텍스트 영역은 약 0.42×0.24m이며 표시 면보다 방 안쪽으로 약 1cm 앞에 놓는다. 위치·배율 계산은 파일 기준이고 최종 가독성은 사용자 확인 대상이다.

최초 구현에는 폰트와 TMP 필수 리소스가 없어 한글 표시가 미완료였다. 이후 사용자가 TMP Essentials와 `Assets/Font/Pretendard-Black SDF.asset`을 적용해 정상 출력을 확인했다. 네 WordText가 같은 폰트를 참조한다. 현재 atlas 설정은 **Static**이다. 최초 제안이었던 Dynamic을 실제 적용했다고 쓰지 않는다. 전체 15,000개 어휘의 모든 글리프나 8글자 가독성을 별도 전수 확인한 기록은 없다.

### 데이터 전달과 재사용

- `RoomViewSnapshot.Capture(map, dataset.GetWord)`는 생성 요청 완료 직후 같은 작업 스레드에서 호출된다.
- 최대 5개 표시 방의 좌표·단어 번호에 더해, 각 방의 네 방향 단어 문자열을 `Signs`에 복사한다. 미생성은 null이다.
- 이웃 방의 표지판에 필요한 주변의 주변도 기존 단어만 조회한다. 방을 새로 생성하거나 표시 범위를 늘리지 않는다.
- `RoomView.Init`은 네 텍스트를 한 번 찾아 보관한다. 매 프레임 이름을 검색하지 않는다.
- `RoomWorldView.Show`는 새 방과 계속 활성인 방 모두 `SetSigns`를 호출한다. null은 `미생성`으로 표시한다.
- 풀 반환 시 `Unbind`가 글자를 비운다. 다른 좌표나 새 실험의 단어가 이전 글자를 덮어쓴다.
- 메인 스레드는 스냅샷만 읽고 TMP를 조작한다. `WordRoom.World`에 Data 참조를 추가하지 않았다.

필수 경로나 TMP가 없으면 새 실험 준비 시 방향·경로를 경고하고 해당 표시를 건너뛴다. 경고는 폰트 지정·텍스트 활성 상태까지 보증하지 않는다. 누락 시험은 Play 종료 후 프리팹 원본에서 한 텍스트를 제거하고 다시 Play해야 한다. 실행 중 인스턴스만 지우면 프리팹 검사와 풀 캐시의 대상이 다르다.

## 3. 출입구·문 높이 (`cf1dd59`)

사용자가 네 출입구와 TestDoor를 함께 수정했다. 바닥 5.2×5.2, 벽 높이 2.8m, 출입구 폭 1m는 유지했다.

| 항목 | 값 |
|---|---|
| 바닥 윗면 | 방 기준 Y 0.05 |
| 출입구 상단 | Y 2.25, 바닥 위 2.2m |
| 출입구 위 인방 | 높이 0.6, 벽 부모 기준 중심 Y 2.5 |
| Door 본체 | Local Position Y 1.1, Local Scale Y 2.2 |
| 문 Collider | 단위 BoxCollider가 본체 스케일을 따라 높이 2.2m |
| 자동 문 상승 거리 | `Door Open Lift=0`이므로 본체 높이 2.2m 사용 |

열림 상태 계산상 문 윗면은 약 Y 4.45이므로 벽 위로 약 1.6m 올라온다. 현재 문 열기·애니메이션은 미구현이므로 실제 열린 화면을 확인한 결과는 아니다.

## 4. 1인칭 이동 (`cf1dd59`)

### 구성과 조작

- 신규 `Scripts/World/FirstPersonPlayer.cs`와 `.meta`를 추가했다. `WordRoom.World.asmdef`에 `Unity.InputSystem` 참조를 추가했다.
- CharacterController는 발 기준 루트, 높이 1.8m, 반지름 0.3m, 중심 Y 0.9, Step 0.3, Skin 0.08이다.
- WASD로 바라보는 수평 방향을 따라 3m/s 이동한다. 입력을 길이 1로 제한해 대각선 가속을 막는다.
- 중력은 `Physics.gravity.y`, 접지 중 하향 속도는 -2m/s다. 점프·달리기·앉기·머리 흔들림은 없다.
- 마우스 좌우는 플레이어 Y 회전, 상하는 카메라 pitch다. 감도 0.1, 제한 ±85°이며 마우스 delta에 deltaTime을 곱하지 않는다.
- Escape·포커스 상실·컴포넌트 비활성화 시 커서를 해제한다. 배치 후 클릭하면 다시 잠근다. 커서 해제 시 이동·시점 입력은 멈추지만 배치된 플레이어의 중력은 계속된다.

### 배치와 생성 연동 범위

1. 새 실험 시작에서 연결된 플레이어를 `Suspend`한다. 아직 첫 배치 전이면 `placed=false`라 낙하하지 않는다.
2. 생성 요청 완료 스냅샷으로 방·문·표지판을 표시한다.
3. `TryGetShownRoom`으로 시작 방 인스턴스를 얻어 `PlaceAt`을 호출한다.
4. `Physics.SyncTransforms` 후 방 중앙 위에서 아래로 Ray를 쏜다. 자기 Collider는 제외하고 가장 가까운 Collider가 해당 방 소속인지 확인한다.
5. 실제 바닥 지점 + skinWidth에 배치하고 상(+Z) 방향·수평 시점·낙하 속도 0으로 초기화한다. 배치 성공 후 조작을 허용한다.
6. 바닥이나 방을 찾지 못하면 오류를 알리고 정지 상태를 유지한다. 단어 생성·Console 출력은 유지한다.

실제 바닥을 읽으므로 worldOrigin의 Y를 포함하며 Y=0에 고정하지 않는다. 이 연동은 시작 위치 배치까지다. 실제 문 통과·엔진 `Move` 호출은 다음 단계다.

### 현재 씬

`Assets/WordRoom/Scenes/RoomGenerationDebug.unity`에 Player와 CharacterController·FirstPersonPlayer가 연결돼 있다. Main Camera는 Player 자식, 로컬 높이 1.6m다. 기존 Camera·URP 데이터와 조명을 유지했다. RoomGenerationDebug.Player가 연결되면 방향키 논리 이동을 막고 `Show(snapshot, player == null)`로 디버그 카메라 자동 이동을 막는다.

near clip은 기존 **0.3**이다. 벽에 근접해 비스듬히 볼 때 잘림이 보이면 0.05~0.1 조정을 검토할 수 있으나 변경 지시는 없었고 확정 버그로 분류하지 않았다.

## 5. 미수정 코드 검토 문제 2건

사용자는 기본 이동 검증 완료를 통보했다. 아래 문제의 수정·실행 재현 완료 통보는 없으며 현재 코드에도 남아 있다.

| 문제 | 조건과 영향 | 필요한 수정 방향 |
|---|---|---|
| 실행 중 Player 칸 해제 | 배치 후 참조를 비워도 이전 FirstPersonPlayer는 계속 동작. 디버그 카메라와 동시 제어하거나 새 실험 중 중력을 적용할 수 있음 | 기존 플레이어를 정지하고 커서 해제, 제어 주체 전환 처리 |
| 비활성 플레이어 배치 | 생성 대기 중 컴포넌트를 끄거나 끈 상태에서 새 실험 시작. null만 검사해 PlaceAt을 호출하고 커서를 잠글 수 있지만 그 컴포넌트의 Update/Escape는 실행되지 않음 | 배치·입력 차단·카메라 제어에 동일한 활성 여부 기준 적용 |

근거는 `RoomGenerationDebug.Update/ShowView/PlacePlayer`와 `FirstPersonPlayer.PlaceAt/Update/OnDisable`이다. 코드 읽기에서 확인한 경로이며 자동 재현하지 않았다. 임시 사용 절차로 디버그 복귀는 **Play 종료 → Player 칸 비우기 → 다시 Play**를 사용한다. 새로운 모드 관리 체계가 필요하다고 단정하지 않고 최소 수정 범위를 후속 프롬프트에서 정한다.

## 6. 사용자 확인 기록과 회귀 확인 범위

- 3D 방·공유 문·풀링과 루트 삭제 수정: 사용자가 Unity 확인 완료 통보.
- 확인용 씬 설정: 사용자 “문제없음” 통보. 해당 연결은 이후 커밋에 포함됐다.
- 벽별 단어·한글 폰트: 사용자가 폰트 변경 후 정상 출력 확인 통보.
- 방 안 1인칭 이동: 사용자가 “검증완료” 통보. `cf1dd59` 커밋 확인.

개별 항목별 상세 결과·성능 측정·전체 글리프 확인은 별도 기록하지 않았다. 이후 변경 시 사용자가 확인할 회귀 범위는 Console과 네 표지판 일치, 기존 활성 방 갱신, 재방문·풀 재사용·새 실험의 글자 초기화, 첫 배치 전 낙하 방지, WASD·시점·충돌·커서, 새 실험 위치 초기화다. 미수정 2건은 수정 후 별도 확인해야 한다.
